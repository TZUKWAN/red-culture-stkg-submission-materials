# 长江流域红色文化时空知识图谱 V2 语义修复研究与执行方案

更新时间：2026-07-14

## 1. 结论

不对 424,150 条断言逐条人工重做，也不推翻已经完成的来源整合、别名归并和格式标准化。

现有 V1 应被定义为“可追溯的全量断言底座和结构化图投影”，而不是最终研究级语义图谱。V2 采用版本化派生重建：保留不可变来源层和原始断言层，批量重算实体类型、时间角色、空间角色、事件框架、历史阶段、CultureState 和演进分析。旧版只读归档，用于对照和回滚。

这里修复的是语义归属，不是重新核查每一条历史事实的外部证据。项目此前已经明确取消逐条事实证据核验，因此本轮重点是同类语义合并、实体消歧、字段统一、关系方向和时间/空间角色修复。

## 2. 为什么不能逐条重做

大规模知识图谱的主流方法不是逐条人工处理，而是：

1. 保留原始来源和声明；
2. 以 Schema、规则、词典、已有知识和模型批量产生候选标签；
3. 融合多个有冲突的判断，保留置信度和来源；
4. 用约束检测错误和不一致；
5. 只把冲突、高风险、低置信度长尾交给模型或人工；
6. 通过分层抽样评估整体质量，而不是把“全部看过一遍”当作质量证明。

EventKG 从多个知识图谱和半结构化来源构建 69 万多个事件、230 多万条时序关系，采用事件识别、关系抽取、同一实体集成、时空与类型融合、来源分图和抽样评价。它只在具有时间有效性信息时抽取时序关系，并把事件自身时间与关系有效期分开建模；融合使用来源投票、可信来源优先和类型本体，而不是逐条手工重写。

DeepDive 将候选生成、数据库规则、统计推断和领域规则结合起来，用机器规模处理知识库构建。Snorkel 使用标签函数表达词典、规则、启发式和外部知识，再学习这些弱标签的准确性及相关性。Knowledge Vault 将文本、表格、页面结构、人工标注和既有知识库的抽取结果做概率融合。共同点都是“程序化监督 + 风险分流”，不是“所有记录都调用一次大模型”。

ArCo 以官方文化遗产目录和编码规范为底座，通过转换器、本体设计模式、能力问题、测试和发布接口形成大规模文化遗产图谱。其经验说明：基础目录记录应保留，错误应在转换和语义层修复，不应反复覆盖来源库。

## 3. 对 V1 的真实诊断

### 3.1 可保留的成果

以下资产不需要推翻：

- 466,312 条来源谱系；
- 424,150 条整合断言及其稳定 ID、原始主客体、原关系、原时间和地点；
- 154,150 个当前规范实体及别名、合并谱系和修复台账；
- 时间字符串规范化、年月日精度保留和统一中文显示格式；
- 长江流域 13 省区市、流域区段和行政层级词表；
- CreativeWork、Spirit、ValueFacet、Artifact 等专题材料；
- 全量导出、哈希、外键、计数、可追溯性、原子发布和回滚基础设施；
- Neo4j 导入结构与来源展开能力。

这些工作解决了“数据从哪里来、同一记录如何聚合、字段如何存、如何追溯和发布”的问题，仍是 V2 的基础。

### 3.2 必须重算的派生层

以下结果不能直接作为论文结论继续使用：

- 实体最终类型；
- 断言时间属于谁、表示什么；
- 断言地点属于谁、表示什么；
- EventFrame 的发生时间和阶段；
- CultureState 的阶段和区域；
- EvolutionTransition；
- 阶段统计、区域统计、网络指标、图表和论文分析；
- 最终 Neo4j 研究视图和监控/浏览界面。

### 3.3 已确认的根因

`scripts/245_build_stkg_event_frames.py` 当前以事件连接的全部断言执行 `min(time_start)` 和 `max(time_end)`，没有判断日期是事件发生时间、人物生平时间、任职有效期、文献出版时间还是纪念活动时间。

只读查询显示，“南昌起义”的 EventFrame 被计算为 `1899-01-01` 至 `1988-12-31`，并横跨 5 个历史阶段。其关联断言中包含“徐明高 1899 年”“王友德 1920 年 11 月”“徐全直 1923 年”等人物或关系上下文时间。该结果不能解释为南昌起义的发生时间。

`scripts/247_build_stkg_evolution_states.py` 又直接使用断言阶段成员关系聚合 CultureState，因此错误时间角色会继续传播到文化状态和演进统计。

实体类型也存在冲突实例：同名“昆明保卫战”同时有 Event 和 Artifact，“中国人民解放军”同时有 Event 和 Organization，“林青”同时有 Event、Person 和 CreativeWork。跨类型同名本身不必然错误，但当前 Event 类型中确实混入组织、人物或作品的风险，必须根据上下文和关系约束重新裁决。

V1 的测试主要证明数据库完整、字段合法、外键不悬空、数量和哈希一致；它没有充分证明“这个日期属于这个事件”或“这个节点类型符合实体语义”。因此测试通过与上述语义错误并不矛盾。

## 4. V2 冻结数据分层

### L0 SourceRecord：不可变来源

保存原始页、记录、路径、来源主键、文本和内容哈希。只读，不覆盖。

### L1 RawAssertion：原始声明

保留现有 424,150 条断言。字段包括原主语、原关系、原宾语、原时间、原地点、来源谱系和当前规范化结果。L1 表示“材料中形成了这条结构化声明”，不自动等于事件事实。

### L2 CanonicalEntity：规范实体注册表

保存规范名称、别名、实体类型候选、最终类型、类型置信度、类型来源和冲突状态。允许同名不同实体，但必须有可解释的消歧键；不能仅凭同名合并，也不能仅凭旧类型保留错误类型。

### L3 ScopedAssertion：带语义作用域的断言

每条 L1 断言派生一条或多条 L3 语义记录，新增关键字段：

- `subject_role`、`object_role`；
- `predicate_family`、`predicate_direction`；
- `time_role`；
- `time_owner_id`；
- `space_role`；
- `space_owner_id`；
- `semantic_status`；
- `confidence`；
- `decision_sources`；
- `risk_flags`；
- `method_version`。

`time_role` 冻结为：

- `event_occurrence`：事件发生时间；
- `relation_validity`：任职、隶属、参与等关系有效期；
- `biographical`：出生、求学、牺牲等人物生平时间；
- `creation_or_publication`：文献、作品创作或出版时间；
- `commemoration_or_reception`：后续纪念、传播、改编或接受时间；
- `source_document_time`：来源文档自身时间；
- `context_time`：只有上下文相关性，不能归属具体实体或事件；
- `unknown`：无法可靠判断。

只有 `time_role=event_occurrence` 且 `time_owner_id=event_id` 的时间，才能定义事件发生时间。`relation_validity` 可用于人物/组织时间线，但不能改写事件发生时间。

### L4 EventFrame：事件框架

由合格的 L3 记录聚合，包含事件类型、发生时间、发生地、参与者、领导者、组织者、对象、原因、结果、影响、子事件、关联物品、文献、作品和纪念活动。没有可靠发生时间的事件允许保留为 `time_unknown`，不得用邻接断言的最早/最晚时间补齐。

### L5 CultureState：红色文化状态

只从语义合格的 L3/L4 记录派生，表示某种红色文化主体在特定时间、空间和文化形态中的状态。Spirit 是可选线索，不是每个状态的必填项。人物、地点、物品也不要求强制成为文化载体。

### L6 EvolutionAnalysis：演进与论文分析

区分三类结果：

- 描述性变化：数量、结构、主体、载体、形态和空间分布随阶段变化；
- 网络性变化：关键节点、社群、跨区域连接和传播路径变化；
- 机制性演进：仅在明确关系和合格支持记录下生成 emerged、spread、transformed、institutionalized、memorialized、adapted 等关系。

描述性先后、相似或共现不能自动升级为因果、继承或传播。

## 5. 批量修复路线

### 阶段 A：冻结 V1 和建立 V2 旁路库

动作：复制发布清单和哈希，不覆盖 V1；创建独立 V2 工作库、决策表和差异表。

验证：V1 文件哈希不变；V2 所有记录可回溯到 L0/L1；迁移前后断言数和来源谱系数一致。

完成标准：没有原始记录被删除、覆盖或静默改写。

### 阶段 B：构造规则和词典标签函数

对全部断言批量运行可解释标签函数：

- 关系 domain/range 约束；
- 人名、组织、事件、地点、文献、作品、文物后缀和词典；
- 已裁决别名和同名消歧台账；
- 主客体方向和事件角色映射；
- 时间触发词、关系词和句法上下文；
- 时间与实体类型组合约束；
- 行政区和地点层级；
- 跨记录的一致性投票。

每个函数可以给标签、反对标签或弃权，不能单个规则直接决定全部记录。

验证：每个函数有命中数、冲突数、弃权数和固定回归样例；对“蔡和森/蔡林彬/林彬”“毛泽东/毛润之”“邓小平/邓希贤”等已有别名决策做专门回归。

完成标准：全量记录均获得机器可解释的标签函数输出，且规则互相冲突时不强行通过。

### 阶段 C：弱监督融合与风险分层

将多规则结果融合成实体类型、时间角色、空间角色和关系语义概率。优先采用简单可审计的加权投票基线，再用小规模已复核样本校准权重；只有基线不足时才训练分类器。

风险层：

- A：多规则一致、无 Schema 冲突，高置信自动接受；
- B：多数规则一致但存在轻微冲突，进入批量二级模型；
- C：跨类型同名、时间归属冲突、复合实体、关系方向冲突，进入 122B 大模型逐候选裁决；
- D：模型仍不一致或信息不足，保留 `unknown/manual_review`，不污染严格图。

验证：输出每层数量、覆盖率、冲突矩阵和置信度校准结果。

完成标准：不以强行补齐为目标；所有未决记录有明确状态，严格层不接收未决记录。

### 阶段 D：定向使用千问 122B

大模型只处理 C 层，不处理全量 424,150 条。每次请求只包含一个候选及其必要上下文、已有别名、相邻关系和 Schema，返回固定 JSON；最多 30 次可恢复重试。

模型任务限定为：

- 同名实体是否同一对象；
- 实体类型和复合实体拆分；
- 时间属于事件、人物、关系、作品还是来源；
- 地点角色和关系方向；
- 同类语义归并。

模型不得凭空补充历史事实；不确定时必须返回 unknown。

验证：JSON Schema、枚举、端点类型、前后逻辑和独立复判；记录模型、prompt 版本和原始响应。

完成标准：所有 C 层候选有可追溯决策或明确未决状态。

### 阶段 E：图约束和全量冲突检测

使用 SQL 约束和图约束检查：

- 关系端点类型是否符合 domain/range；
- EventFrame 发生时间是否只来自 event_occurrence；
- 人物生平时间是否错误写到事件上；
- 作品创作、纪念活动和来源时间是否错误回写历史事件；
- 同一实体是否存在不可解释的跨类型冲突；
- 时间区间是否倒置或伪精确；
- 阶段、地区和流域区段是否与合格时间/空间角色一致；
- CultureState 是否由合格事实支持；
- 演进关系是否有前后状态及允许的关系语义。

Neo4j/RDF 发布时可用 SHACL 或等价的 SQL/Cypher 门禁。W3C SHACL 明确定义了根据 shapes 对 RDF 数据图进行条件校验的标准机制。

完成标准：严格发布层严重约束违规为 0；未决和冲突记录只进入背景层。

### 阶段 F：抽样评估和误差驱动迭代

按实体类型、关系族、时间角色、历史阶段、省区市、文化形态、置信度和风险层分层抽样。人工只判断结构语义是否正确，不重新做外部史实证据调查。

重点评价：

- 实体消歧准确率；
- 实体类型准确率；
- 时间角色与时间归属准确率；
- 空间角色准确率；
- 事件角色准确率；
- CultureState 合法率；
- 演进关系精确率。

发现系统性错误后，不逐条修补同类记录，而是新增或修正规则，对全量重跑，再复测受影响切片。

完成标准：严格层各关键指标达到合同阈值；置信区间、样本构成和错误类型全部公开，不只报告总体平均值。

### 阶段 G：重建派生层和发布 V2

按 L3 -> EventFrame -> CultureState -> EvolutionAnalysis -> Neo4j 的依赖顺序重建。重新生成论文统计、图表和能力问题结果；旧 V1 继续保留为归档基线。

验证：全量合同测试、哈希、外键、语义门禁、抽样指标、能力问题、Neo4j 中文显示、时间轴/地图/关系网联动和回滚演练。

完成标准：V2 研究视图可以回答“何时、何地、什么红色文化、由谁通过什么事件或载体形成、传播和转化”，且每个答案可回到 L1 来源声明。

## 6. 效率预期与调用边界

424,150 条断言都要经过批量程序处理，但不等于 424,150 次大模型调用。

高置信规则层用 SQL/Python 批量完成，通常是分钟到小时级；模型只处理规则冲突和语义歧义。实际模型任务量必须在阶段 B/C 完成后按真实分层计数，当前不能虚构一个固定数字。目标是把模型量压缩到全量的小部分，同时不以牺牲严格层质量换速度。

不再重读三十多万页原文。只有当现有结构化上下文不足以裁决一个高价值歧义时，才回到对应来源片段；普通未决长尾可保留为 unknown。

## 7. 不再推翻的变更控制

从 V2 开始冻结以下原则：

1. L0/L1 不可变；
2. 所有修复写入版本化决策表，不原地覆盖；
3. 时间值与时间角色分开；
4. 实体类型、关系语义、事件框架、文化状态和演进分析分层；
5. Spirit 是线索而非强制中心；
6. CultureCarrier 是可选角色而非所有实体的必备类型；
7. 未知是合法结果，不以填满字段为成功；
8. 新规则先过回归样例和影响预演，再全量运行；
9. 派生层可以重算，来源层永不丢失；
10. 每次发布都保留旧版本、差异报告和回滚路径。

后续若研究问题不变，只能新增规则、词表、模型或分析视图，不再改变上述层级语义。这样即使算法升级，也只是重算派生层，不会再次推翻基础数据。

## 9. 执行终态（2026-07-15）

本方案的 L0-L7 路线已完成实现并通过全量审计。最终状态如下：

- V1 保持只读，SHA-256 未变化；
- 424,150 条断言和 466,312 条来源关联全部守恒；
- 152,979 个规范实体完成最终类型与身份投影；
- 最终实体类型闭包只调整 208 条失效时空角色，没有把既有 context 判断提升为强事件角色；
- 28,065 个 EventFrame、7,067 个事件时空单元和 11,532 个 CultureState 已重建；
- 159 个演进候选中 4 个显式结构关系通过发布门禁；
- 1,019 个文艺作品全部具有媒介字段，57 个信息不足项保留为“未知”；
- 26 个能力问题全部只读执行通过；
- Neo4j 完整图为 1,062,247 个节点、2,984,015 条关系；
- 全量结构审计、分层抽样、Neo4j/UI 验证均为 PASS。

实施中新增并冻结一条变更控制原则：实体身份融合或类型修正后，必须在物化研究层前执行时空角色的最终类型闭包；闭包只修复不再满足类型约束的角色或仍为 unknown 的结构化时间，不覆盖仍合法的既有审定。每个变化写入 `research_scope_adjustments`，可追溯、可回滚。

后续新增材料时继续沿用同一增量路线：只向 L0/L1 追加来源和声明，运行实体/关系/时空语义增量处理，重建受影响派生层并发布新版本。不得在 V2 发布库内直接手工修改单条结果，也不得删除未解决记录以提高表面通过率。
